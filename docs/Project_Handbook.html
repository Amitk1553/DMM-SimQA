What the meter does

Imagine testing a program that reads a 2.3456 V supply. On a bench you would connect leads, select DC voltage, pick a range and read the display. Here Python holds the input in memory. Your control program sends the same kind of text commands over a local socket and gets a display string back. You can reproduce overloads, resets and disconnects without moving a lead.

TermMeaning in this project
DMMDigital multimeter. It measures direct-current voltage in volts, direct current in amperes, or resistance in ohms. DC means the modeled input is steady in time until changed.
SCPIStandard Commands for Programmable Instruments. The simulator implements the documented subset. Colons separate levels of a command header. A question mark requests a reply. SOUR:SIM and SOUR:NOISE are simulator controls.
Range / resolutionRange sets the largest valid input. Resolution sets the displayed increment. A 5 V range with 0.001 V resolution can display 2.346 V. Resolution alone says nothing about physical accuracy.
Noise / overloadNoise models reading-to-reading variation. Overload means the true input falls outside the configured interval. These conditions have different responses.
Loopback / port127.0.0.1 addresses this computer. A TCP port selects the listening service. Port 5025 is the default and port zero asks the OS to select a free port.
QA / oracleQuality assurance here includes test design, reproducible execution and defect evidence. An oracle is the rule used to decide whether an observation passes.

Follow one reading end to end

Client → TCP worker → SCPIParser → VirtualDMM
Client ← ASCII reply + LF ← formatted reading
StepCommand or eventWhat changes or comes back
1*RSTThe parser calls reset(). Voltage mode, 100 V full scale, input zero, output off, noise on, FIFO empty.
2CONF:VOLT:DC 5The parser converts 5 to a float. The model validates the range before committing mode and range together.
3SOUR:SIM 2.3456The model stores the finite input. No measurement has happened.
4SOUR:NOISE OFF then OUTP ONThe next reading will be deterministic. OUTP is a software measurement gate.
5MEAS:VOLT:DC?The client appends LF. A worker extracts the line. The parser normalizes and dispatches it under its lock.
6VirtualDMM.measureThe gate is open, the mode matches and 2.3456 lies between 0 and 5 inclusive. The voltage formatter rounds to three decimals.
72.346The worker appends LF to the reply. The client reads through LF, strips the terminator and gives the caller a Python string. Units follow from the configured mode.

Predict the next reply. Keep the configuration and set the input to 5.0001. Its display digits could hide the small excess, but the range check sees the raw input first. The next measurement returns 9.9E+37. Reading SYST:ERR? twice gives -222 and then 0. Repeating the measurement would enqueue another overload.

State and measurement decisions

ModePermitted input at default rangeDisplay incrementGaussian σ
VOLT:DC0–100 V0.001 V0.005 V
CURR:DC0–10 A0.001 A0.002 A
RES0–1,000,000 Ω0.1 Ω0.5 Ω

CONFIGURE accepts a positive full scale up to the mode maximum. Omitting it restores the maximum for that mode. Zero is a valid signal but an invalid range. Changing mode leaves the stored signal, output gate, noise flag and queue intact. The same stored number acquires the new mode’s units. Closing and opening a client also preserves settings on a running server.

Decision orderResult
1. Output offReturn zero formatted for the requested function. Even an excessive signal leaves the queue unchanged.
2. Requested mode differsRaise SettingsConflictError. The parser returns and queues -221.
3. Raw signal outside [0, range_limit]Queue -222 and return the overload string 9.9E+37. Both endpoints are valid.
4. Valid inputWhen noise is on, add a sample drawn from a zero-mean Gaussian with the mode’s standard deviation. Clip the result to [0, range_limit], then format it to the mode’s decimal places.

At a rail the clipping makes the distribution asymmetric. That is why the noise tests use an interior signal of 5. When noise is off, the resistance function displays 0.001 Ω as 0.0 Ω because its smallest display increment is 0.1 Ω. A formatted zero can therefore also mean a small valid input.

Command grammar and diagnostics

SendInterpretation or response
*IDN?SimQA-Labs,DMM-34401A,SQ001234,1.2.0 (manufacturer, model, serial number, firmware).
*RST / *CLSReset restores all instrument defaults and clears errors. Clear removes only queued errors.
CONF:VOLT:DC [range] / CONF:CURR:DC [range] / CONF:RES [range]Select a function and optional full scale. Brackets mark an optional argument in this guide. Omit the brackets on the wire.
CONF?Two comma-separated fields, e.g. RES,5.0.
OUTP ON / OUTP OFF / OUTP?Enable, disable or inspect the gate. The query returns 1 or 0.
SOUR:SIM <value> / SOUR:NOISE ON or OFFInject a finite value or switch noise. A finite input may exceed full scale so that clients can exercise overload handling.
MEAS:VOLT:DC? / MEAS:CURR:DC? / MEAS:RES?Read the selected function with its display precision, subject to the ordered decisions above.
SYST:ERR?Pop the oldest diagnostic. An empty queue returns 0,"No error". Each read consumes evidence.

The parser strips outer whitespace, uppercases, splits fields, removes one optional leading colon and expands keywords by lookup. For example, ‘ :configure:voltage:dc 2e0 ’ selects a 2 V range. Full forms include CONFIGURE, VOLTAGE, CURRENT, RESISTANCE, OUTPUT, SOURCE, SIMULATE, MEASURE, SYSTEM and ERROR. Arbitrary prefixes and semicolon-separated commands fall outside this grammar.

InputImmediate replyNext SYST:ERR? on an initially empty queue
BADNo reply-100,"Command error"
CONF:RES ABCNo reply-102,"Syntax error"
CONF:CURR:DC 11No reply-222,"Data out of range"
MEAS:RES? while enabled in voltage mode-221,"Settings conflict"-221,"Settings conflict"
FOO?-100,"Command error"-100,"Command error"
Valid query with empty diagnosticsRequested value0,"No error"

A numeric token must match the whole decimal/scientific-notation pattern. NaN is a syntax error. The token 1e999 passes the grammar, converts to infinity and fails numeric validation. These are different defects in an incoming command and they get different codes.

Sockets, concurrency and shutdown

TCP delivers an ordered stream of bytes. A receive call can return half a command or several complete lines. Each worker accumulates bytes in a bytearray, extracts every LF-terminated frame and retains the unfinished tail. It accepts up to 4096 bytes per frame including LF. CRLF works because the parser strips surrounding whitespace. An oversized frame closes that connection. EOF discards an incomplete command. Invalid ASCII in a complete line queues a syntax error.

The server gives every worker the same parser. Its lock surrounds an entire command including queue updates. Two clients can interleave between CONF and MEAS, so a multi-command measurement sequence needs coordination by the callers. tcp_client follows its reset write with OUTP? on the same stream. Getting a reply confirms the server processed reset before the fixture hands control to the test.

The client's default socket timeout is three seconds. query('*CLS') sends a valid write, then waits for a reply that will never arrive. The resulting timeout closes the session so a later call cannot consume stale bytes. Conversely, write('*IDN?') leaves an unread reply for the next query. Pair the API method with the command type.

Server startup binds the port and starts a listener thread. A separate lifecycle lock serializes start and stop. On stop, the listener signals workers, ends the accept loop, joins the listener thread and closes the server while waiting for workers. Workers check the stop event after receive waits of 0.25 seconds. They preserve a partial command across ordinary receive timeouts. The lifecycle test keeps a client connected through stop to exercise this path.

Run a complete bench session

In Windows PowerShell open the project root and run the following commands. Leave the first terminal running. On later starts reuse the existing environment.

python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
.\.venv\Scripts\python -m dmm_simqa.server --port 5025

In a second PowerShell terminal in the same directory set the source path and start the interpreter. On Linux or macOS, create the environment using python3, use .venv/bin/python for installation and startup, and set export PYTHONPATH=src in each terminal.

$env:PYTHONPATH = "src"
.\.venv\Scripts\python

At the Python prompt, paste the following and finish the indented block with a blank line. Use the port printed by the listener if you chose --port 0.

from dmm_simqa.client import SCPIClient

with SCPIClient("127.0.0.1", 5025, timeout=2) as meter:
    meter.write("*RST")
    print(meter.query("*IDN?"))   # SimQA-Labs,DMM-34401A,SQ001234,1.2.0
    print(meter.query("CONF?"))   # VOLT:DC,100.0
    print(meter.query("OUTP?"))   # 0
    meter.write("SOUR:NOISE OFF")
    meter.write("SOUR:SIM 2.3456")
    print(meter.query("MEAS:VOLT:DC?"))  # 0.000 while output is off
    meter.write("OUTP ON")
    for mode in ("VOLT:DC", "CURR:DC", "RES"):
        meter.write(f"CONF:{mode} 5")
        print(mode, meter.query(f"MEAS:{mode}?"))
    # VOLT:DC 2.346, CURR:DC 2.346, RES 2.3
    meter.write("SOUR:SIM 5.0001")
    print(meter.query("MEAS:RES?"))  # 9.9E+37
    print(meter.query("SYST:ERR?"))  # -222,"Data out of range"
    print(meter.query("SYST:ERR?"))  # 0,"No error"
    meter.write("CONF:RES ABC")
    print(meter.query("SYST:ERR?"))  # -102,"Syntax error"
    meter.write("BAD")
    meter.write("*CLS")
    print(meter.query("SYST:ERR?"))  # 0,"No error"
    meter.write("*RST")

Exit the Python interpreter with exit() and stop the server in the first terminal with Ctrl+C. For an unexpected zero, check the gate, mode, signal size and resolution. For a connection refusal, check the listener and port. For a timeout, check whether the command actually produces a reply.

Interview practice

Try answering aloud, then check the reasoning. For design questions, explain the current behavior first and label any proposed extension. For defect questions, distinguish the observed shutdown hang from the two fault-injection exercises.

Explain the project

How would you introduce this project in a minute?

DMM-SimQA lets a control program operate a virtual multimeter over TCP. I would demonstrate an exact voltage reading, push the same meter over range, then retrieve the diagnostic. Those three actions connect the measurement model, SCPI protocol and automated QA evidence.

Who benefits from the simulator?

A developer can exercise instrument-control code without reserving a physical bench. A QA engineer can deliberately repeat edge cases, and a CI runner can execute the same tests on every proposed change.

What does SCPI compliance mean here?

The contract covers the command subset in the reference, its long and short headers, query responses and diagnostics. Interoperability with a particular hardware driver still requires checking every command and transport feature it uses.

What belongs in the model and what belongs in the parser?

The model decides whether an input overloads and how many digits to display. The parser interprets text such as CONF:RES 5 and maps domain failures to SCPI messages. This lets both in-process and socket tests exercise the same measurement rules.

How would you demonstrate the project without networking?

Construct SCPIParser(VirtualDMM()), call execute('*IDN?'), then send configuration and measurement commands through execute. This exercises normalization, state and replies. Use the integration suite to demonstrate the socket layer separately.

What evidence would you show in an interview?

Open the traceability row for a reduced-range overload, run its exact pytest node, and explain why 0.10001 V exceeds a 0.1 V range. Then show the full report, coverage gate and the corresponding fault-injection record.

Instrument and protocol

What is the difference between voltage, current and resistance here?

Voltage measures potential difference, current measures charge flow and resistance measures opposition to current. In the model they select different units, full scales, noise levels and display precision. The simulated input is supplied directly in those units.

Is zero a legal range? A legal input?

A configured range must be strictly positive. A signal of zero is within every supported range. CONF:RES 0 queues -222, while a deterministic enabled resistance measurement at zero returns 0.0.

Does changing the mode convert the input?

The model keeps the numeric value. Switching from voltage to resistance reinterprets that value in ohms. A realistic experiment usually sets the input again after a mode change.

Why accept a negative voltage input?

The source helper represents the external signal, including a signal outside this unipolar meter’s capabilities. Setting it succeeds if it is finite. An enabled voltage measurement then reports overload.

What exactly happens at full scale?

The raw upper bound is inclusive. With noise off, a 100 V signal on the 100 V range returns 100.000. A 100.001 V signal returns 9.9E+37 and queues -222.

Which wins if the output is off and the mode is wrong?

The output gate is checked first. After reset MEAS:RES? returns 0.0 with an empty FIFO. With output enabled, that same query returns and queues -221.

Can a numeric-looking reply represent an error?

Yes. 9.9E+37 is the overload sentinel. A caller should recognize it before converting an ordinary reading to engineering units. The FIFO supplies the associated -222 diagnostic.

How do reset, clear and error query differ?

*RST restores defaults and clears the FIFO. *CLS clears only the FIFO. SYST:ERR? removes just the oldest error. A second client can consume an error the first client caused.

How are numbers and long headers parsed?

A full-token regex accepts signed decimal and exponent notation. A lookup normalizes each recognized long keyword. An optional leading colon, mixed case and surrounding whitespace are accepted.

Why compare before rounding?

At a 0.1 V limit both 0.1 and 0.10001 round to the same voltage display. Comparing the formatted value would accept a true overload. The instrument compares the stored input first.

Does reset reproduce the same sequence of noisy readings?

Reset restores the noise flag and clears the signal. The existing random generator retains its state. A fresh fixture constructs a fresh generator with the fixed seed 34401.

Python and networking

Why use a frozen dataclass?

MeasurementSpec groups the four related characteristics of a function. Freezing protects each record's fields from accidental reassignment. The mode lookup remains an ordinary dictionary.

Why use custom exceptions?

Invalid settings can be detected where their meaning is known. The parser catches a common DMMError and uses the subclass code to generate the wire diagnostic. Socket errors follow a separate transport path.

What does the context manager guarantee?

Entering opens the socket and buffered reader. Exiting closes both, including when the user's block raises an exception. Attempting to re-enter an already connected client raises RuntimeError.

Why use sendall and an LF terminator?

sendall attempts to transmit every byte or raises an error. LF defines the application message boundary because TCP itself preserves only byte order.

What if two commands arrive in one packet?

The worker loops over complete LF-delimited lines in its pending buffer. It executes them in order on that connection and carries any trailing partial line into the next receive.

What if a client disconnects halfway through OUTP ON?

Without the terminating LF the command is still pending. When recv returns an empty byte string the worker exits and the partial write has no effect.

Is a 4096-byte command allowed?

A complete 4096-byte frame including its LF is allowed. A 4096-byte payload followed by LF exceeds the budget. The server closes the connection for an oversized frame.

Does the GIL make the parser lock unnecessary?

The protocol needs a whole read/validate/update command to act as a unit across threads. Python interpreter scheduling gives no such application-level transaction guarantee.

Could two clients configure different modes at once?

Their individual commands execute one at a time. The last successful configuration becomes shared state. One client can change the mode between another client's configure and measure commands.

Why give each thread its own client?

A shared connection has one reply stream. Concurrent readers could associate a reply with the wrong request. The server already supports separate connections to the same instrument.

Why bind tests to port zero?

The OS allocates an available port during bind. Tests retrieve server.port afterward. This avoids the race between checking a candidate port and binding it.

How would you diagnose a server hanging on exit?

Keep an idle client connected during stop and capture thread stacks. A worker stuck in a blocking read while the caller joins workers points to shutdown coordination. SIMQA-101 records that observation and the bounded-receive fix.

Testing and QA

What are the test fixtures and their lifetimes?

dmm is fresh per case. tcp_server is shared for the integration module and stopped in finally. tcp_client opens a fresh connection per requesting case, resets the shared instrument, checks OUTP? and closes on exit.

Why use pytest parameterization?

The same behavior has several inputs and expected outputs. Each parameter becomes a separately selectable case. An exact maximum in resistance can fail independently of the equivalent voltage case.

How do smoke and regression selections differ?

Smoke contains four basic readiness cases. Regression selects the twelve functional cases because that module has both markers. Adding their counts together would double-count those cases.

Give a boundary analysis example.

Select the voltage range and examine zero, one display count above zero, exact maximum, just above maximum and a negative signal. A reduced-range excess smaller than one display count tests the order of validation and rounding.

Give an equivalence partitioning example.

For configuration arguments, choose one valid number, malformed text, a nonpositive range and an excessive range. The parser and model take distinct paths, with different effects on state and diagnostics.

How do you check noisy measurements without a flaky exact comparison?

Use a seeded generator and sample 400 readings at input 5. Check mean against 5 with absolute tolerance 0.2σ and sample standard deviation against σ within 15%. This catches a disabled or badly scaled noise model.

Why would sampling noise right at zero be misleading?

Clipping maps negative excursions to zero. The resulting sample has a shifted mean and a different spread. Interior inputs isolate the intended Gaussian noise behavior.

Does the statistical test establish Gaussianity?

Mean and spread checks on one seeded sample establish limited regression evidence. Several non-Gaussian distributions can pass them. A distributional requirement would need additional evidence.

How do you test a failed write?

Assert it has no synchronous reply, read the exact pending error, inspect the relevant state and verify the next FIFO read returns zero. This catches unintended partial updates.

Why synchronize concurrent test clients with a barrier?

It brings four connected workers to the same starting point. Each sends a bad command and a query. Draining four errors after completion checks shared state under overlapping traffic.

What is the difference between timeout and a disabled-output zero?

A timeout raises a transport exception and closes that session. Disabled output is a successful query with a formatted zero. SYST:ERR? stays empty if it was empty before that measurement.

Why test in-process and over sockets?

Parser tests isolate protocol and model semantics quickly. Loopback integration exercises real byte framing, connection ordering, worker synchronization and cleanup that a direct Python call bypasses.

How do severity and priority differ?

Severity describes impact. Priority expresses urgency. A server-wide shutdown hang was Critical/P0. A wrong overload decision is Major/P1 because it can make a reading look valid.

Which reported defects were actually observed?

The Windows shutdown hang was observed during integration. The rounded-range comparison and omitted reset clear were deliberately introduced in temporary copies. Their failures show that specific regression tests detect those changes.

What is traceability?

A requirement such as REQ-LIMIT links to a case ID, exact command steps, expected result and pytest node. The report supplies execution evidence for that node. The CSV status is a recorded snapshot.

What does 91.82% coverage measure?

The reference run executed 247 of 269 measured source statements. The threshold is 90% for the whole package. A covered statement can still contain an untested boundary or branch.

Which checks enforce the release decision?

Pytest failures, warnings promoted to errors, unknown markers and low aggregate coverage fail the run. Review of complete case mappings and outstanding defect severity is also part of the formal test plan.

Delivery, debugging and design trade-offs

What happens when a change targets main?

GitHub Actions runs on pushes and pull requests targeting main. Bitbucket runs the shared QA step on main and on pull requests. Both install pinned direct QA dependencies on Python 3.11, run pytest and capture its HTML report.

What does the pipeline deploy?

Its deliverable is test evidence. The workflows publish the HTML report as an artifact. Starting a persistent simulator service is a local operator action.

Why can all selected tests pass while a coverage check fails?

A focused run may touch only a small fraction of the package. Use --no-cov while isolating one case, then rerun the full suite to apply the configured coverage gate.

How would you diagnose a deterministic reading that keeps changing?

Query the active configuration and gate, disable noise, set the source again, and inspect the FIFO. Run with one client to rule out shared state changing between commands.

Why might the next query return the previous reply?

If a caller used write for a query, the server sent a line that the client never consumed. Reconnect to start with a fresh stream and use query for each reply-producing command.

What would you inspect before retrying a timed-out write or query?

The server may already have executed the command. Reconnect and inspect current state where possible. Repeating SYST:ERR? can consume a second diagnostic and repeating a measurement can enqueue a second overload.

Where are the scaling limits?

Each connection has a worker thread and all commands serialize at one parser. The FIFO is an unbounded Python list whose front removal shifts later entries. Load requirements would guide connection limits, queue policy and use of deque.

How would you add an AC voltage mode?

Define its units, limits, display precision and measurement semantics first. Add the mode specification and any parser aliases or special behavior. Exercise configuration, valid values, overload and TCP round trips, then extend the matrix and reference.

How would you compare this simulator with a real meter?

Run representative command transcripts against the target instrument and compare replies, errors, timing and reset behavior. The simulator currently omits calibration, physical transients, hardware trigger timing and vendor-specific features outside its reference.

What improvement would you test next?

One small addition would be paired transport cases at the exact maximum valid frame length and one byte beyond it. The current suite covers oversized traffic. The pair would make an off-by-one change to frame handling easier to detect.
